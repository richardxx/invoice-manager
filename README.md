# 本地发票管理

收发票，认归属，算报销。一个人用得上，几个人一起报销也用得上。

## 月底记

办公室里的人，是肯报销的。至于发票在哪里，却各有各的说法。一位说在邮箱，一位说在微信；还有一位寄来一个压缩包，打开以后仍是压缩包。他大约觉得，票藏得深些，钱便也安全些。

我逐张找出来，认开票方，认金额，再问这是谁的。四张发票明明归了 张三，表上却端端正正地写着「¥0.00」。我望着这两个零，它们也望着我，彼此都没有解释。

有人劝我把 Excel 再做细些。这意见很稳妥，因为说这话的人不必在夜里翻「最终版」「最终版2」和「这次真的是最终版」。也有人说，票少的时候，记在脑子里就好。可到了月底，票未必少，脑子倒先不够用了。

于是我同 Codex 写了这个软件。发票进来，先收好原件；认不清的，明说认不清；归谁、算哪月，由人决定。它不能替人报销，却能使人不必为了报销，把同一张票找上三遍。

—— **0x2frogs**

## 要办的事

| 遇到的问题 | 软件怎样处理 |
| --- | --- |
| PDF 散在各处，有的还藏在 ZIP 里 | 拖入 PDF 或 ZIP，逐层查找；导入结果逐一列出，漏掉的可手动补入。 |
| 发票认不出开票方、金额或消费类型 | 先读 PDF 自带的文字；关键字段缺失，再用本地 OCR。AI 识别须由用户手动发起。 |
| 票找到了，却说不清是谁报、哪月报 | 归属人和报销月份分别指定，不拿开票日期代替报销月份。 |
| 月底要重算金额、重找原件、重命名文件 | 按月、按人、按类型汇总；导出前逐张预览并修改文件名。 |
| 银行代发资料要再抄一遍 | 从人员资料和当月已核对的报销金额生成指定格式的 Excel。 |
| 换一版软件，怕旧账跟着没了 | 原件和 SQLite 数据库留在工作目录；迁移目录时复制、校验，并保留旧目录。 |

## 设计理念

**原件留下，判断交给人。** 导入后的 PDF 不因修改识别结果而改写。软件可帮忙提取字段，却不能证明一张发票是真的，也不能替人决定它该不该报销。拿不准的票标为「待核对」。

**能在本机做的，就在本机做。** 导入、PDF 文字提取、OCR、归属和汇总不依赖在线服务。只有用户主动选择「AI 识别发票」，才会把发票页面图像发往其自行配置的兼容 OpenAI 协议的服务。

**日期、归属、状态各记各的。** 开票日期是票上的日期，报销月份是人选的月份；「待核对」说的是识别结果，「已报销」说的是付款进度。把它们混成一栏，月底又要猜谜。

**省事，也得让人心里有数。** 未归属的票排在前面；批量归属、合计所选金额，都有明确结果。导出前先给清单，文件名可以改，已有的月份文件夹不会被悄悄覆盖。

## 在 Windows 上运行

构建需要 **JDK 25** 和 **Maven 3.9+**。本机 JDK 安装在 `D:/Program Files/Java`；项目不附带 Java 运行时。进入项目目录后执行：

```powershell
cd "D:/program/InvoiceManage"
mvn test
mvn package
& "D:/program/InvoiceManage/Run-InvoiceManage.ps1"
```

没有把 Maven 加入 `PATH` 时，可用已有的本地 Maven 执行同样的构建命令。构建后也可运行项目根目录的 `InvoiceManager.cmd`。启动脚本使用 `work/run-cache/` 中经过校验的 JAR 副本，正在运行的软件不会因下一次构建而被替换；构建过程中不要直接运行 `target/` 下的 JAR。

默认工作目录为 `%LOCALAPPDATA%/LocalInvoiceManager`。在 **设置 → 选项 → 系统** 中可改到新的空目录。软件会复制并校验旧数据，保留原目录，随后重启。`%LOCALAPPDATA%/InvoiceManageBootstrap` 只记录当前工作目录的位置。

如要使用独立的测试数据目录，可从项目根目录运行：

```powershell
./InvoiceManager.cmd --data-root="C:/path/to/test-data"
```

## 日常怎样用

1. **先登记人员。** 在「人员管理」里选预设头像，填姓名、卡号或账号、户名、收款行类型、CNAPS 号及证件资料；双击姓名可修改。人员列表显示累计已完成报销额。固定的「公司」账户不用填个人收款资料，也不写入银行代发 Excel。
2. **把票收进池里。** 拖入 PDF 或 ZIP，也可点「添加发票」。ZIP 内的文件夹和嵌套 ZIP 都会查找；结果窗口列出处理过的 PDF。双击可打开原件，多选漏报文件后可补充导入。相同文件会提示已存在。
3. **核对识别内容。** 新票先走 `PDF_TEXT`，缺关键字段再走 OCR。已有的票可在右键菜单中重新 OCR；配好模型后，也可手动用 AI 识别。扫描件和机票行程单尤其要检查开票方、金额、日期、类型。未核对的票不会进入导出。
4. **指定报销人和月份。** 右键选「归属于」；多张票可用 Ctrl/Shift 选中后批量归属。未归属的排在前面，已归属的另有标记。多选时可用「计算金额」查看已识别金额的合计。
5. **按月查看。** 「报销管理」只列出当月有归属发票的人，按消费类型统计金额，并标出待核对数量。双击人员、金额或待核对数量可看明细；单击只选中单元格。
6. **完成或撤销报销。** 确认付款后点「完成报销」；需要更正时点「撤销报销」。已完成的月份须先撤销，才能再接收新归属发票。每张票和每个月的状态都记在工作目录的数据库里。

## 导出

- **导出发票包：** 先看当月发票清单，逐张检查报销人、金额、类型和文件名；文件名可直接修改。确认后选择目录，软件在其中新建 `yyyymm` 文件夹，复制原始 PDF。已有同名月份文件夹不会被覆盖。
- **导出银行 Excel：** 使用内置 `MixedOtherPaymentExcelTemplate.xls` 中的「其他代发批量文件-混合」工作表，每位符合条件的个人收款人占一行。「公司」不导出；个人资料缺项时，会列出缺什么，并停止生成。

月度表会显示已归属发票中已知的正金额；导出则只收已经核对的票。若从发票池删除尚未报销的票，已归属的会先提示取消归属。原件和删除记录仍留在工作目录，重新导入相同 PDF 可以恢复；已报销的票须先撤销报销。

## 数据放在哪里

- 工作目录保存发票原件、人员资料、SQLite 数据库与报销记录。软件升级不应清掉这里的数据。
- 目前收取的是 **PDF 发票**，ZIP 只是装票的容器。OFD/XML、云同步、审批、税务查验及会计申报尚不支持。
- 识别出的开票方指销售方或出票单位；购买方、乘车人、报销归属人各是各的，不由软件擅自合并。
- Windows 上，AI API Key 由当前用户的 DPAPI 保护，不进入备份；其他平台仅在当前会话中保留。备份和导出的 PDF、银行 `.xls` 文件本身**不加密**，请妥善保管。
- `mvn package` 生成 `target/invoice-manager-1.5.12.jar`，并清理旧版及 `original-` 前缀的 JAR；不会打包应用或源码 ZIP。扫描件 OCR 需要 `tessdata/`。

依赖与 OCR 模型署名见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)；实现和测试细节见 [docs/system-design-v5.md](docs/system-design-v5.md)。软件的「帮助 → 使用方法」有图解；「帮助 → 关于」有六幅漫画。画面上点三下，它才肯自己往下演。
